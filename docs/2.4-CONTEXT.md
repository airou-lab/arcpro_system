# Phase 2.4: GUI Verification - CONTEXT

## Goal
Verify that the 200,000-step trained `RecurrentPPO` policy can successfully navigate one full lap of the OpenStreetUSD map using a GUI-enabled Isaac Sim session.

## Decisions

### 1. Visual Overlays & UX
*   **Waypoint Visualization:** Use a **2D Top-down Map** window in the UI to show the planned trajectory relative to the robot.
*   **Camera Layout:** Implement a **Side-by-Side** view showing both the high-resolution 360p rendering and the 160x90 downsampled view the AI uses.
*   **Telemetry:** Display **Simple Text** in the corner for speed (m/s), steering angle, and throttle percentage.
*   **Confidence Indicator:** Include a status indicator for the Lane Detector's current confidence.

### 2. Inference Control
*   **Loop Behavior:** Non-continuous. The robot should complete **one full lap**.
*   **Termination:** Upon lap completion, the simulation should **Stay Paused** rather than exiting, allowing for final position inspection.
*   **Reset Logic:** Enable **Auto-Reset** on collisions or track departure.
*   **Keyboard Overrides:**
    *   `R`: Force manual reset.
    *   `Space`: Toggle Pause/Resume.
*   **Stuck Detection:** Trigger auto-respawn if speed remains below 0.1 m/s for > 5 seconds.

### 3. Verification Criteria (Success)
*   **Completion:** One full lap completed without manual intervention.
*   **Performance:** Average rollout speed must be consistently **> 1.0 m/s** (confirming resolution of the passivity trap).
*   *Note: Quantitative Lateral Deviation and robustness (lighting) tests are deferred to Phase 3/4.*

### 4. Documentation Strategy
*   **Format:** Detailed Technical Report (`PHASE_2_TECHNICAL_REPORT.md`).
*   **Structure:** Problem -> Root Cause -> Fix table.
*   **Content:** Must include code snippets of critical patches (LSTM fixes, initialization order) and performance graphs.
*   **Lessons Learned:** A dedicated section capturing "gotchas" for Isaac Sim background training.

## Deferred Ideas
*   High-fidelity lateral deviation tracking.
*   Environment randomization tests (lighting, weather, textures).
*   Multi-robot parallel inference tests.
